# Project Governance

## Overview

cryptoptic is an open-source project licensed under the [Apache License 2.0](LICENSE). This document describes how the project is governed, how decisions are made, and how community members can participate.

## Roles

### Users

Anyone who uses cryptoptic. Users are encouraged to participate by:

- Filing bug reports and feature requests via GitHub Issues.
- Participating in discussions.
- Helping other users.

### Contributors

Anyone who contributes to the project through code, documentation, tests, reviews, or other means. Contributors are expected to:

- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).
- Submit changes via pull requests.
- Engage constructively in code reviews and discussions.

### Maintainers

Maintainers are responsible for the overall direction, quality, and release management of the project. Their responsibilities include:

- Reviewing and merging pull requests.
- Triaging issues and managing the project roadmap.
- Ensuring adherence to coding standards and security practices.
- Managing releases.
- Enforcing the Code of Conduct.

The current list of maintainers is documented in [MAINTAINERS.md](MAINTAINERS.md).

## Decision-Making Process

- **Day-to-day decisions** (bug fixes, minor improvements) are made by any maintainer via pull request approval and merge.
- **Significant changes** (new features, architectural changes, breaking changes) require discussion in a GitHub Issue or Discussion before implementation and approval from at least two maintainers.
- **Governance changes** require consensus among all maintainers. Where consensus cannot be reached on a governance change, a simple majority vote among maintainers will decide the outcome.

## Becoming a Maintainer

New maintainers are appointed exclusively by the existing maintenance team. Community nominations or self-nominations are not accepted.

1. An existing maintainer identifies and nominates the candidate internally.
2. The nomination is discussed and evaluated among current maintainers.
3. Approval requires unanimous agreement from all existing maintainers.
4. The new maintainer is added to [MAINTAINERS.md](MAINTAINERS.md).

## Removing a Maintainer

A maintainer may step down voluntarily at any time. A maintainer may also be removed by consensus of the remaining maintainers if they are no longer active or have violated the Code of Conduct.

## Contributions

All contributions are subject to the [Apache License 2.0](LICENSE). By submitting a pull request, you agree that your contribution is licensed under the same terms.

## Changes to Governance

This governance model may be amended by consensus of the maintainers. All changes will be documented via pull request.
